# Compare (Compare spec, Part C) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Diff code and data across a database and its comparison partner (Part B), at these levels:
- a **file**;
- a **module** (a pick list of added, removed and changed files);
- a **Python class or method**;
- an **XML record, template or menuitem**;
- a **database record** (its stored field values).

Every compare opens VS Code's diff editor. The partner's side is on the left (B2). Real files stay real files, so the right side can be edited.

**Architecture:**
- **Pure core.** `src/services/compare/` holds:
  - `counterpart.ts`: finds the same file in the other side's code;
  - `moduleDiff.ts`: lists the differences between two module trees;
  - `pythonSymbols.ts`: an indentation scanner, plus finding a method by `_name`/`_inherit`;
  - `xmlElements.ts`: the XML element under the cursor, and the same id elsewhere;
  - `recordCompare.ts`: parses a record reference, builds the SQL, renders values.
- **Runtime.** `src/services/compare/sides.ts` turns a database into its code roots (version core trees, project repos). The commands are in `src/commands/compareCommands.ts`. Virtual sides use Part B's `odoo-compare:` snapshots.

**Tech Stack:** TypeScript, VS Code API (`vscode.diff`, `executeDocumentSymbolProvider`), psql.

**Spec:** `docs/superpowers/specs/2026-10-07-compare-and-multi-server-design.md`, Part C (C1–C3) and §5. The user said "go ahead" on 2026-10-08. Part B's partner rules are in force: `partnerFor`, `comparisonSides`, and `withCheckpointOpen` for every read of a checkpoint.

## Global Constraints

- **Repo rules.**
  - Branch `v-1.5` only; never merge or push.
  - Leave `.vscode/launch.json`, `.vscode/tasks.json` and the root dotfiles alone. Add files by name. **Never use `git stash`**: the stash is shared with other sessions.
  - Commits: `[ADD]`/`[IMP]`/`[FIX]`/`[REF]`/`[DOC]`, ending with a `Co-Authored-By:` trailer that names the model that wrote them. dist/ only in the last task.
- **Which databases a code compare uses.**
  - "This side" is the upgrade's To side in upgrade mode; otherwise it is the selected database.
  - "The partner" is `partnerFor(project, thisDb, { ask: true, onStored: refresh })`.
  - A file that belongs to the partner's code compares to this side's code. A file in neither side's code says "<file> is not part of <db>'s or <partner>'s code."
  - A checkpoint partner runs the same code as its database, so a code compare with one says: "A checkpoint runs the same code as <db>. Compare code with a database partner." Record compare does work with a checkpoint.
- **Left and right.** The left side is `comparisonSides(thisDb, partner, pair).left`'s side, and the right side is the other. Diff titles are `<what>: <left label> ↔ <right label>`. A label is a database name, or a checkpoint's label.
- **When both sides resolve to the same file** (same version, same checkout), the command says "<file> is the same file in <left> and <right>." and opens nothing (C3).
- **Counterpart search (C1).** The steps, in order:
  1. the same root and the same relative path;
  2. the same file name inside the counterpart module's folder;
  3. a module of the same name in the other side's addons folders, with the same relative path inside it;
  4. a quick pick of up to **50** files with the same name in the other side's addons folders;
  5. otherwise "<x> has no counterpart in <side>."
- **Module compare.** Files are compared by size, then by SHA-1 of the content. The quick pick shows changed, added and removed files with a summary line ("3 changed · 1 added · 2 removed"). Picking one opens its diff. An added or removed file is diffed against an empty snapshot labelled "(not in <side>)". `__pycache__`, `*.pyc` and dot-folders are skipped.
- **Class and method.**
  1. The enclosing symbol comes from `vscode.executeDocumentSymbolProvider`, with the indentation scanner as fallback.
  2. The counterpart is the same qualified name (`SaleOrder._compute_amounts`) in the counterpart file.
  3. Otherwise search the counterpart module's `.py` files for a class with the same `_name`, or the same `_inherit` when there is no `_name`, that defines the method.
  - Both sides are snapshots.
- **XML element.** The element under the cursor is a `<record>`, `<template>` or `<menuitem>` with an `id`. Look for the same `id` in the counterpart module's XML files, comparing a bare id and `module.id` alike, the module part being the counterpart module's name. Both sides are snapshots.
- **Database record.**
  - Input: an external id (`module.name`), or `model,id` / `model id`.
  - Read with SQL through `runSql`:
    - `ir_model_data` resolves an external id;
    - `ir_model_fields` (`store = true`) lists the stored fields, intersected with the table's real columns from `information_schema.columns`;
    - the row is read with `row_to_json`.
  - Rendering:
    - translated (jsonb) values show their `en_US` value, falling back to the first key;
    - `binary` fields show "<n> bytes, sha1 <first 12>";
    - one line per field, `field: value`, sorted by field name;
    - a record missing on one side gets an empty side with "(no such record in <db>)".
  - A checkpoint partner is read inside `withCheckpointOpen`.
  - Identifiers go through `quotePgIdentifier`, text through `sqlText`, and ids are validated integers.
- **Menus.**
  - "Compare with Partner" (file) is in the editor title "…" menu (not inline), in the editor context menu and in the Explorer context menu for files.
  - "Compare Module with Partner" is on Modules view rows (`viewItem == module`) and in the Explorer context menu for folders.
  - "Compare This with Partner" is in the editor context menu for `.py` and `.xml` files.
  - "Compare Record…" is on database rows (`viewItem == database`) and in the palette.
  - None is hidden in upgrade mode.
- **Verification:**
  - `npx tsc -p . --noEmit` and `npm run lint` (0 errors, 117 warnings baseline).
  - Tests run outside the sandbox: `npm run compile-tests && env -u ELECTRON_RUN_AS_NODE npx vscode-test --grep "<suite>"`; the full suite is `npm test`. Baseline: 1011 passing, 38 pending, 0 failing.

## Review Focus

1. **A module renamed or split between versions** (`account_edi` in 16 against `account_edi_ubl_cii` in 17, or a file moved into another module). The search falls back in the C1 order and never opens a wrong same-path file from an unrelated root. (Task 1 tests on fake trees.)
2. **Overlapping roots.** One side's repo sits inside another root, or the Odoo root contains `odoo/addons`. The longest matching root wins. (Task 1 test.)
3. **A cursor in a nested function or a decorator line**, or in a class body outside any method. The scanner picks the innermost class or method, and a decorator belongs to the function below it. (Task 3 test.)
4. **A record whose model has no table** (an abstract or transient model), or a translated field stored as text before 16. Each gets a clear message or a plain value, never a SQL error toast. (Task 4 tests.)
5. **Large modules** (`account`, about 2,000 files). The module diff hashes only same-size files, and reads them lazily. (Task 2 test asserting that no hash is computed for different-size files.)

## Rulings made while planning

- **C-R1.** A code compare with a checkpoint partner refuses with a message, because the code is the same. Record compare works with checkpoints — cost if wrong: none.
- **C-R2.** "This side" follows the View Doctor's target rule: the upgrade's To side, else the selected database — cost if wrong: a user who wanted another database selects it first.
- **C-R3.** File compare opens real files on both sides when they exist. The left file is a real file too, so it can be edited; VS Code's diff allows that — cost if wrong: an edit on the partner's side touches the partner's checkout, which is what the user typed into.
- **C-R4.** Symbol and XML compares show snapshots on both sides, because they are excerpts — cost if wrong: you edit in the file, not in the diff.
- **C-R5.** The module tree diff skips `__pycache__`, `*.pyc`, `.git` and other dot-folders, and `node_modules` — cost if wrong: none.
- **C-R6.** Compare Record from the palette uses this side (C-R2). From a database row it uses that row's database as this side — cost if wrong: none.

### Task 1: Where the other side's code is (C1)

**Files:**
- Create: `src/services/compare/counterpart.ts`, `src/services/compare/sides.ts`
- Test: `src/test/compareCounterpart.test.ts`

**Interfaces:**
- Produces, in counterpart.ts:
  - `interface CodeRoot { role: string; path: string }`. The role identifies the same root on the other side: `odoo` for the Odoo root, `core:odoo/odoo/addons`, `core:odoo/addons`, `core:enterprise`, `core:themes`, or `repo:<name>`.
  - `interface SideRoots { label: string; roots: CodeRoot[] }`
  - `rootOf(file: string, side: SideRoots): { root: CodeRoot; rel: string } | undefined`. The longest matching root wins. `rel` uses `/`.
  - `interface FsProbe { exists(p: string): Promise<boolean>; isDir(p: string): Promise<boolean>; list(dir: string): Promise<string[]> }`. `list` returns entry names.
  - `type Counterpart = { kind: 'found'; path: string } | { kind: 'pick'; candidates: string[] } | { kind: 'none' }`
  - `resolveCounterpart(file: string, from: SideRoots, to: SideRoots, fs: FsProbe): Promise<Counterpart>`
  - `addonsRoots(side: SideRoots): CodeRoot[]`, meaning every role except `odoo`.
  - `realFsProbe: FsProbe`
- Produces, in sides.ts:
  - `sideRootsFor(project, db: { id: string; versionId?: string }, label: string): Promise<SideRoots | undefined>`. It builds the roots from the version's `odooPath` (role `odoo`) and `coreAddonsPaths` (roles from position: the enterprise path is `core:enterprise`, the design-themes path is `core:themes`, `<odoo>/odoo/addons` is `core:odoo/odoo/addons`, and `<odoo>/addons` is `core:odoo/addons`), plus the project repos `resolveReposForDatabase(project, db)`, each `repo:<repo.name>` at its resolved path.
  - `codeSides(project, options: { ask: boolean; onStored?: () => void; db?: string }): Promise<{ thisDb: string; partner: ResolvedPartner; left: SideRoots; right: SideRoots; thisSide: 'left' | 'right' } | { error: string } | undefined>`. It returns undefined when the user dismissed a prompt. It applies C-R1 (a checkpoint gives an error) and C-R2.

import * as fs from 'node:fs/promises';
import * as os from 'node:os';
import * as path from 'node:path';
import { resolveCounterpart, rootOf, realFsProbe, SideRoots } from '../services/compare/counterpart';

async function touch(file: string, text = 'x') {
    await fs.mkdir(path.dirname(file), { recursive: true });
    await fs.writeFile(file, text);
}

suite('Compare: counterpart files', () => {
    let tmp: string;
    let s17: SideRoots;
    let s18: SideRoots;

    setup(async () => {
        tmp = await fs.mkdtemp(path.join(os.tmpdir(), 'odt-cmp-'));
        const side = (v: string): SideRoots => ({
            label: `odoo${v}`,
            roots: [
                { role: 'odoo', path: path.join(tmp, v, 'odoo') },
                { role: 'core:odoo/odoo/addons', path: path.join(tmp, v, 'odoo', 'odoo', 'addons') },
                { role: 'core:odoo/addons', path: path.join(tmp, v, 'odoo', 'addons') },
                { role: 'core:enterprise', path: path.join(tmp, v, 'enterprise') },
                { role: 'repo:acme', path: path.join(tmp, v, 'acme') }
            ]
        });
        s17 = side('17');
        s18 = side('18');
        await touch(path.join(tmp, '17/odoo/addons/sale/models/sale_order.py'));
        await touch(path.join(tmp, '18/odoo/addons/sale/models/sale_order.py'));
        await touch(path.join(tmp, '17/odoo/odoo/models.py'));
        await touch(path.join(tmp, '18/odoo/odoo/models.py'));
        await touch(path.join(tmp, '17/acme/acme_sale/views/sale.xml'));
        await touch(path.join(tmp, '18/acme/acme_sale/views/sale_views.xml'));

        // a module moved from enterprise to community
        await touch(path.join(tmp, '17/enterprise/web_studio_lite/models/a.py'));
        await touch(path.join(tmp, '18/odoo/addons/web_studio_lite/models/a.py'));
        // renamed module: the same file name exists in two other modules
        await touch(path.join(tmp, '17/odoo/addons/account_edi/models/edi_format.py'));
        await touch(path.join(tmp, '18/odoo/addons/account_edi_ubl/models/edi_format.py'));
        await touch(path.join(tmp, '18/enterprise/account_edi_x/models/edi_format.py'));

    test('the longest matching root wins', () => {
        const hit = rootOf(path.join(tmp, '17/odoo/addons/sale/models/sale_order.py'), s17);
        assert.strictEqual(hit?.root.role, 'core:odoo/addons');
        assert.strictEqual(hit?.rel, 'sale/models/sale_order.py');

        assert.strictEqual(r.kind, 'pick');
        assert.strictEqual((r as { candidates: string[] }).candidates.length, 50);
    });

- [ ] **Step 3: Implement `counterpart.ts`.**
  - **`rootOf`.** Normalise with `path.resolve`. A root matches when the file equals the root path or starts with the root plus `path.sep`. The longest match wins. `rel` is the relative path, split and rejoined with `/`.
  - **`resolveCounterpart`**, in this order:
    1. Find `hit = rootOf(file, from)`. If there is none, return `none`.
    2. **Same root, same path.** If the `to` side has the same role and `join(toRoot.path, rel)` exists, return `found`.
    3. If `hit.root.role === 'odoo'`, go to step 6. Otherwise `module` is the first segment of `rel`, and `inner` is the rest.
    4. **The counterpart module.** If `join(sameRoleRoot, module)` is a folder on the `to` side, walk it and collect the files whose basename equals `basename(file)`. The walk skips dot-folders, `__pycache__` and `node_modules`, and stops at depth 8. One file is `found`; several are `pick`.
    5. **The module in another root.** For each other `to` addons root that has a folder `<module>`: if `join(folder, inner)` exists, return `found`. Otherwise collect the same-basename files inside it, as in step 4. One is `found`; several are `pick`.
    6. **Same name anywhere.** Walk all of the `to` side's `addonsRoots` and collect up to 50 files with the same basename. One is `found`, several are `pick`, none is `none`.
  - **`realFsProbe`** uses `fs.promises`. `exists` is a stat that resolves to a boolean; `list` is `readdir` and returns `[]` on error.
  - Keep each walk bounded at depth 8.

- [ ] **Step 4: Implement `sides.ts`.**
  - `sideRootsFor` is as described in the Interfaces. Resolve the version with `VersionsService.getInstance().getVersion(db.versionId)`. It returns undefined when the version is unknown.
  - `codeSides`:
    1. `thisDb` is `options.db` or `resolveViewDoctorTarget(project).dbName`.
    2. Get `partner = await partnerFor(project, thisDb, { ask: options.ask, onStored: options.onStored })`.
    3. If `partner.kind === 'checkpoint'`, return the C-R1 error.
    4. Otherwise get `sides = comparisonSides(thisDb, partner, upgradePair(project))`. Build the `SideRoots` for both, labelled by database name (or the checkpoint label), and return them with `thisSide`.
  - No unit test is needed for `codeSides` (vscode-bound). `sideRootsFor` role mapping gets one small test with a fake version: add `sideRolesFor(settings, repos)` as a pure helper and test that.

### Task 3: Compare This with Partner (class, method, XML element)

**Files:**
- Create: `src/services/compare/pythonSymbols.ts`, `src/services/compare/xmlElements.ts`
- Modify: `src/commands/compareCommands.ts`, `package.json`
- Test: `src/test/comparePythonSymbols.test.ts`, `src/test/compareXmlElements.test.ts`

**Interfaces:**
- Produces:
  - `interface PySymbol { kind: 'class' | 'function'; name: string; qualified: string; start: number; end: number }`. `start` and `end` are 0-based line numbers, `end` exclusive, and `start` includes the decorators.
  - `scanPythonSymbols(text: string): PySymbol[]`

  - `symbolText(text: string, s: PySymbol): string`

import { enclosingSymbol, findMethodInSources, modelKeyOf, scanPythonSymbols, symbolText } from '../services/compare/pythonSymbols';

const SRC = [

    '',                                    // 1

        assert.strictEqual(enclosingSymbol(symbols, 11)?.qualified, 'SaleOrder');
